# CLAUDE.md — frontend

Guidance for Claude Code working inside `frontend/`. Repo-wide context is in the root `CLAUDE.md`; the product brief is `../specs/product.md`.

## Commands

Run from `frontend/`. Dependencies are not installed by default (`npm i` first).

```sh
npm run dev        # vite dev server
npm run build      # production build: the AWS Amplify Hosting server in .amplify-hosting/ (nitro preset aws_amplify)
npm run preview    # run that server locally, on :3000 (the port Amplify's runtime uses)
npm run lint       # eslint (prettier runs as an eslint rule, so lint fails on formatting)
npm run format     # prettier --write .
npm test           # vitest, one pass
npm run test:watch # vitest, watching
npm run typecheck  # compiles the messages (npm run i18n), then tsc --noEmit
npm run i18n       # regenerate src/paraglide from messages/*.json (dev, build and npm test already do)
npm run i18n:check # fails when messages/en.json and fr.json differ in keys or {variables} (npm test runs it)
```

The dev server proxies `/api` to the Python backend on `:8000`, configured through the `vite` key in `vite.config.ts`. Nothing works until that backend is running — see `../documentation/running-locally.md`.

Vitest has its own `vitest.config.ts`, deliberately separate from `vite.config.ts`: the app config registers TanStack Start and the deploy server, an SSR/nitro pipeline the unit tests do not need.

## Stack

React 19 + TanStack Start (SSR) on Vite 8, Tailwind v4, shadcn/ui (new-york, slate base) on Radix, KaTeX for math, TanStack Query wired but unused so far. TypeScript is strict, with `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess` and `noPropertyAccessFromIndexSignature` on — index access yields `T | undefined` and index-signature properties need bracket access.

`vite.config.ts` lists its plugins directly: Tailwind, TanStack Start (with `src/server.ts` as its server entry), Nitro at build time only (preset `aws_amplify`: static files plus a Node.js compute function in `.amplify-hosting/`), React and Paraglide. The `@/…` paths are Vite's own tsconfig paths (`resolve.tsconfigPaths`, as in `vitest.config.ts`). The nitro preset is `aws_amplify` unless `NITRO_PRESET` says otherwise (the Docker image builds with `node-server`, see `../documentation/docker.md`). `src/server.ts` registers the language strategies by name: the package is `sideEffects: false`, so a bare `import "./lib/i18n"` there is dropped from the build and the first visitor of a fresh server would get French whatever their browser says.

Interface text is French, English or Dutch (specs 010 and 017, `../documentation/i18n.md`), through Paraglide JS: `messages/fr.json` (base), `en.json` and `nl.json` compile into typed functions in `src/paraglide/` (generated, gitignored). Write `m.some_key({ name })` from `@/paraglide/messages` **inside a function**; never call one at module scope (a table holds `m.some_key`, not `m.some_key()`; ESLint forbids the call). Every key lives in all three files, plurals use the inlang selector form, Zod schemas are factories called in render. French text in a component is an ESLint error outside `lib/tutor/prompts.ts` (what the model is told the learner said), `lib/locale.ts`, `lib/error-page.ts` and `charts/format.ts` (the board's notation and vocabulary, per course language). Course text (Célestin's messages, cards, chapter titles, pack, path) follows the **course's** language (spec 011), whatever the interface language, and is marked `lang={language}` with `const language = useCourseLanguage()` (`src/lib/course-language.tsx`; the course, chapter, content and discussion routes provide it from what the server sent, French outside a provider). The board's notation is `useNotation()` / `notationFor(language)` in `charts/format.ts`; the sentences the interface sends to the model for the learner are `useLearnerSentences()` in `lib/tutor/prompts.ts`. Tests run in French (`src/test/setup.ts`); `withLocale("en" | "nl", fn)` runs a body in that language, and every screen has an English-sweep test (and a Dutch one) that fails on French (or English) text outside a region that carries its own `lang`.

## Architecture

- **Routing** is file-based under `src/routes/`. `src/routes/README.md` holds the naming table; `routeTree.gen.ts` is generated (by the Vite plugin on `npm run dev`/`build`), never hand-edited. Do not introduce `src/pages/` or `app/layout.tsx` — those are Next/Remix conventions and will not work here. `login.tsx` and `register.tsx` are public and server-rendered; `_auth.tsx` is the authenticated layout (`ssr: false`, `beforeLoad: requireUser` → `context.user`, the not-yet page for non-students). Since 005, under it: `_auth/courses/index.tsx` (« Mes cours »), `_auth/courses/$courseId/index.tsx` (the course page: chapters, add, rename, delete), `_auth/courses/$courseId/chapters/$chapterId/index.tsx` (the lesson, `components/celestin/lesson.tsx`, or the preparation state), `…/$chapterId/discussion.tsx` (discussion mode, `components/celestin/discussion-panel.tsx`) and `…/$chapterId/content.tsx` (« Contenu du chapitre » and its editors); `index.tsx` redirects to `/courses`. Spec 012 adds `_auth/admin/index.tsx` (« Administration »: the accounts, enable, disable, reset a password; `components/celestin/admin/`, `lib/admin.ts`): the `_auth` guard sends an admin who opens a student page to `/admin` and anyone else who opens `/admin` to `/courses`, and `login.tsx` / `register.tsx` follow the registration mode (`authConfigQuery`: no link when closed, a « Compte créé » screen in verification mode; `register()` returns `{status: signed_in | pending}`). Route tests mount the real files through `src/test/route-harness.tsx`.
- **`src/routes/__root.tsx`** is the only shell: HTML document (`<html lang>` is the interface language), head tags, fonts, KaTeX stylesheet, `QueryClientProvider`, `LocaleBoundary` (remounts the tree when the language changes), 404 and error boundaries. It must keep rendering `<Outlet />`.
- **Server entry** is deliberately custom. `src/server.ts` wraps TanStack Start's server entry in `paraglideMiddleware` (the request's language for the render), adds `Vary: Accept-Language` and `Cache-Control: private, no-cache` to HTML (`lib/html-headers.ts`; Amplify's CDN would otherwise share one language's page), and catches errors h3 swallows into a JSON 500 to render `lib/error-page.ts` (in the browser's language) instead; `src/start.ts` installs the request middleware and re-adds the CSRF middleware that Start would have installed automatically had `start.ts` been absent. Removing either silently loses error reporting or CSRF protection on server functions.
- **The lesson screen** is `src/components/celestin/lesson.tsx`, mounted by the chapter route: a slim bar (`chapter-bar.tsx`, shared with the discussion route: course, chapter, the « Parcours | Discussion » switch, « Contenu du chapitre », user, sign-out), tutor column left, whiteboard right, resizable divider on desktop; below `lg` the board takes the screen with Célestin's last message as a caption and the composer under it, and the bar is `←`, the two modes and a `⋯` menu (`tutor-board-split.tsx`, `tutor-caption.tsx`, `composer.tsx`, `chapter-path.tsx`; `useCompactLayout()` tells a component which frame it is in; `LessonFrame` fits the screen to `useVisualViewport` so the keyboard does not cover the composer; `../documentation/lesson-layout.md`).
- **Settings** (spec 010): `components/celestin/user-menu.tsx` (the name, « Paramètres », sign-out; shared by the courses bar and the chapter bar) leads to `routes/_auth/settings.tsx`, whose shell (`settings/settings-page.tsx`) renders the sections registered in `settings/sections.ts`. The sections are the language and, since spec 012, the password; a new setting is a component and an entry there. Changing the language saves `PATCH /api/auth/me`, then `setLocale(l, { reload: false })` and `router.invalidate()`; leaving a lesson for the settings is an ordinary navigation (the parcours transcript is in memory only).
- **Auth and data** live in `src/lib/auth.ts` (`meQuery`, `login`/`register`/`logout`, `requireUser`, `safeRedirect`), `src/lib/tutor/courses.ts` (subjects and limits, courses, chapters, content, the editors' saves, the document uploads; the course query polls every 3 s while a chapter is being prepared) and `src/lib/tutor/chapter.ts` (the lesson view; chapter and progress come together). Fetches carry the session cookie automatically; nothing stores a token.

### The tutor transport (`src/lib/tutor/`)

- `types.ts` — mirrors the backend DTOs. The SSE event set is a **two-sided contract**, specified in `../specs/001-tutor-chat-agent/design.md` §3.2 (plus the two section events in `../specs/002-chapter-sections/design.md` §3.2) and pinned by golden transcript tests in the backend. Changing it here means changing it there.
- `sse.ts` — pure chunk-to-frames parser, so it can be tested against byte fixtures.
- `client.ts` — `streamEvents(url, body, signal)` reads one turn's stream and yields typed events whichever route serves it; `streamTurn` is the parcours call over it, posting the transcript with `{course_id, chapter_id}`; `getJson`/`sendJson`/`sendForm` (multipart, no content-type header so the browser sets the boundary) and `ApiError` for every other route.
- `chapter.ts` — `chapterQuery(courseId, chapterId)`: the overview plus the student's progress, always refetched; `409 chapter_not_ready` for a chapter still in preparation.
- `courses.ts` — subjects, course list and detail, create/rename/delete, `addChapter(courseId, files)` and `replaceDocument` (006: a chapter comes from one PDF or photos, sent as repeated `files` fields in page order; there is no paste), retry/delete chapter, content query, `savePack`/`saveCurriculum`/`saveSource` (the transcription editor), `resetChapter`. `ApiError.issues` carries the reasons a content edit was refused.
- `path.ts` — display-only mirror of the backend's locked path, tested against the same case table (`__tests__/path_cases.json`, copied from the backend). It colours rows; it cannot unlock anything.
- `chapter-model.ts`, `labels.ts` — the strip's view model, and the section-kind, state and voice labels as maps of catalog message functions (`KIND_LABEL[kind]()`; the interface language, spec 010). `prompts.ts` holds the French sentences the interface sends to the model for the learner.
- `discussion.ts` — discussion mode (spec 007): the conversation query, « Nouvelle conversation », the turn transport (which posts the *message*, the server holding the transcript) and the spoken-turn report.
- `health.ts` — the `/api/health` query; `voice: false` keeps the telephone inert, `dictation: false` hides the composer's microphone.
- `voice/` — voice mode (spec 003): `realtime.ts` (the Realtime event subset and client event builders), `bridge.ts` (pure Realtime-event → `TutorEvent` mapping, tested on JSONL fixtures; one is a recorded session), `session.ts` (`VoiceSession`: mic, `RTCPeerConnection`, the `oai-events` channel, injectable for tests), `client.ts` (the three `/api/voice` routes). Set `localStorage.celestinVoiceRecord = "1"` to log every server event as a `celestin.voice` console line for a new fixture.

### The Célestin components (`src/components/celestin/`)

The product surface. The chat column, the board, the chapter map, the mic and the camera are driven by the real tutor and models.

- `use-tutor-session.ts` — all session state for the page load, plus the chapter progress. It takes an optional `transport` and `initialState`, so one hook and one `reduce` serve both modes; `sessionFromEntries` folds a stored discussion back through that same reducer, so transcript, board history and markers cannot drift. In the parcours the conversation is not persisted; the progress is owned by the server (004): it arrives with the chapter as `initialProgress`, changes only through the section events the backend has already stored, and a reset goes through the API. There is no `localStorage` progress any more. The `reduce` function is a pure reducer over SSE events plus two client-internal ones (`voice.on`, `voice.off`), which is where the tests live. Every state change goes through `apply`, which writes the ref before React, so a synchronous reader (the voice tool queue) never sees stale progress. Start and teardown share one effect on purpose; split in two, a re-invoked effect aborts the opening turn that the guard then refuses to restart. The hook returns a `handle` (`dispatch`, `appendLearner`, `markInterrupted`, `snapshot`) that is all the voice hook may touch.
- `use-voice-session.ts` — the voice orchestration: phase machine, seed, serial tool queue (`/api/voice/tool` → `dispatch(event)` → state item → `function_call_output` → one `response.create`), cap and idle timers, mute, second-tab guard, usage report on stop and on `pagehide`. All browser objects come through `VoiceDeps`, so the tests run under jsdom with fakes. The route picks `voice.sendText` over `session.send` while a session is open, for the composer and the board buttons alike.
- `discussion-panel.tsx` — discussion mode: loads or creates the conversation, restores it, and mounts the same tutor column and board without the strip, the map or the page-turn button (nothing there can move the path). The lesson mounts it *beside* itself and hides the lesson rather than navigating away, because the séance's transcript lives in memory only.
- `chapter-strip.tsx` — the always-visible position strip under the tutor header (a flat line above the board on a phone; `chapter-path.tsx` pairs it with the map); `chapter-map.tsx` — the sheet with the full path, review and start actions, and the reset. Component tests run under jsdom (`// @vitest-environment jsdom`) with Testing Library.
- `whiteboard.tsx` — renders whichever card is current, plus a history strip of the cards Célestin wrote this session. The board starts empty; the scaffold's mock cards are gone. Cards have no buttons of their own: acting on the board means talking to Célestin. Every card component takes its DTO as props. The check-question card reports the picked option through `onAnswer`, and the « Étape suivante » button under the card fires `onNextStep`; the route turns both into learner messages so the tutor sees them. The button is live only between a `step.ready` event and the next card or turn.
- `board-blocks.tsx` — renders typed blocks and splits `$…$` out of prose for KaTeX. **No model output ever becomes HTML**; that is why the board takes typed blocks rather than Markdown. `BlockView` dispatches the four drawing blocks (`chart`, `flowchart`, `figure`, `plot`); a worked example's or an exercise's `drawing` is the `Drawing` union of `types.ts`, rendered by the same `BlockView`. `RichText mathOutput="mathml"` is for screen-reader-only text, because KaTeX's html output is aria-hidden.
- `charts/` — the `chart` block (spec 008), drawn with our own SVG from the statistics Célestin gives: `chart-view.tsx` (frame, axis titles, pie legend, the screen-reader table, which writes values only when `show_values` does), one component per kind (`bars`, `sticks`, `histogram`, `cumulative`, `pie`, `box`), `axes.tsx` (`valueFrame` + `CartesianSvg`, the shell the four counting charts share; thinned or rotated labels; box-plot label lanes), and the pure `format.ts` (decimal comma, `12,5 %`, `[a ; b[`; also `formatPair` for « (2 ; −1,5) » and `formatInterval` / `formatBound` for intervals with ±∞, which `figure/` and `plot/` use: the board's notation is written in this one file), `scale.ts` (nice ticks), `series.ts` (`sanitise`, applied once in `ChartView` so a replayed malformed chart never reaches a component; `entries`, the labelled series every table and legend reads; histogram areas, polygons, cumulative points, arcs). Drawn at the measured pixel width (`use-width.ts`), never a scaled `viewBox`. Nothing on a chart reacts to the pointer. Recharts (`ui/chart.tsx`) is installed but unused: it has no box plot or unequal-width histogram. Chart labels are SVG text, so the backend refuses `$` in them; the three drawing folders below draw geometry in SVG and put Célestin's text in an HTML layer over it, so their labels may carry maths.
- `flowchart/` — the `flowchart` block (organigramme):
  - `graph.ts`: `sanitise`, applied once in `FlowchartView` (a hidden node's text becomes « ? » there, so it never reaches the DOM; a blank label counts as none), `readingOrder`, `pathState`;
  - `layout.ts`, pure: `layers` (shared with the backend's `wide` rule through `__tests__/layer_cases.json`, a byte-identical copy of `backend/tests/fixtures/flowchart_layers.json`), `structure`, `fit`, `arrange`, `layoutFlowchart` (null below `MIN_SCALE` 0.85: the board then lists the steps). Tracks are ordered so that no two edges into different boxes run along each other, and `__tests__/invariants.ts` checks it (`sharedStretches`);
  - `shapes.ts`: metrics (compact below 360 px), boxes, outlines;
  - `measure.ts` / `use-label-sizes.ts` / `measure-layer.tsx`: each label measured once at five widths (`LADDER`) in a 0 × 0 hidden layer, `measuredSize` taking a wrapped label's widest line from its inline RichText span; estimated in jsdom;
  - `describe.ts`: the step list, where every step says where it leads;
  - `flowchart-view.tsx`: an SVG of geometry with HTML labels over it, scaled to 85 % at most, else the visible list; an sr-only list with MathML.
- `figure/` — the `figure` block (plane geometry, number lines, diagrams of sets):
  - `figure-view.tsx`: sanitises once, then `role="img"` with the sr-only description as MathML;
  - `plane.tsx` + `plane-scene.ts`; `number-line.tsx` + `line.ts` (lanes, notation, and the hatching, which belongs to a lane: what none of its pieces holds, drawn once);
  - `sets.tsx` + `venn.ts`: the layouts, with `fits` pinned to the backend's `crowded` rule by `__tests__/capacity.json`, a byte-identical copy of `backend/tests/fixtures/figure/capacity.json`;
  - `label-layer.tsx`: labels as HTML over the SVG (`w-max` spans, KaTeX, zone flows);
  - `labels.ts`, `geometry.ts`, `describe.ts`;
  - `sanitise.ts`: total. It drops numbers beyond ±1e6 (`MAX_MAGNITUDE`) and ignores spans under 1e-9 (`MIN_SPAN`), so no tick computation can throw.

  It reuses charts' `format` (numbers, `formatPair`, `formatInterval`), `scale` and `use-width`. Test hooks, never handlers: `data-marker` (a point's marker), `data-zone` (a zone of sets), `data-mark` (a placed number's dot, never drawn on an interval's bound) and `data-hatch` (a lane's hatching).
- `plot/` — the `plot` block: graphs in a cartesian plane drawn from Célestin's mathematics.
  - `expression.ts`: our expression grammar, the browser's half of `backend/app/domain/expression.py`, tested on `__tests__/expression_cases.json` (a byte-identical copy of the backend's table);
  - `sanitise.ts`: total cleaning at the edge (an absurd window becomes [−10 ; 10]);
  - `ticks.ts`: axes through 0 or on an edge, steps, labels thinned to a round multiple;
  - `sample.ts` (`sampleCurve`): adaptive sampling; a gap whose midpoint does not split its rise is a pole or a jump;
  - `groups.ts`: the colour key (same label, same colour);
  - `labels.ts`: plain screen-reader text, size estimates, the occupancy grid, label placement (a point's coordinates come from charts' `formatPair`);
  - `layout.ts`: every geometric decision, DOM-free, including the y title's side and the corner labels moved off the other axis's line;
  - `describe.ts`: the aria-label and the sr-only description, which never states an expression, a domain or an endpoint;
  - `plot-view.tsx`: draws the scene. Célestin's text is KaTeX spans over the SVG, and the caption has a MathML copy for screen readers.

  Like charts, nothing on a flowchart, figure or plot reacts to the pointer.
- `tutor-column.tsx` — the desktop column: header, transcript, retry (on a phone it renders `TutorCaption` and the composer instead); `composer.tsx` — composer, symbol palette, stop, the camera (`photo-button.tsx`: a phone's camera and gallery through file inputs, a computer's webcam in `webcam-dialog.tsx`; `use-photo-work.ts` and `lib/tutor/work.ts` send the photo, a vision model reads it, and the text lands in the field to be corrected: the tutor never sees the picture, `../documentation/work-reading.md`), and the microphone, which is **dictation** (`use-dictation.ts`: a take that ends by itself, `lib/tutor/dictation/vad.ts`, then `POST /api/dictation`; text lands in the field, never sent for her), or the call's mute during a call; `call-button.tsx` — the telephone that starts and ends the voice session. Talking is the telephone, dictating is the microphone: never the other way round (mic toggle, mute, end, phase label with the countdown, the spoken-entry icon). The textarea stays enabled during a voice session.
- `math.tsx` — the single KaTeX entry point, running with `trust: false`. Render all math through `<Math tex=... />` so tutor content and learner input are typeset identically; `output="mathml"` (default `"html"`) is for text only a screen reader reads, since KaTeX's html output is aria-hidden. KaTeX is self-hosted under `public/katex/`, not loaded from a CDN.

- Course page: `course-header.tsx` (the « ⋯ » menu holds rename and delete), `course-resume.tsx` + `lib/tutor/featured-chapter.ts` (« Reprends où tu en étais »), `chapter-row.tsx` (a card: one filled button, « Contenu du chapitre » and « Supprimer » in its menu), `progress-bar.tsx`, `subject-icon.tsx`; a menu item opens a confirmation through `ConfirmDialog`'s controlled `open` (a dialog inside the menu would close with it); `../documentation/accounts-and-courses.md`.
- Course pages (005, 006): `document-picker.tsx` (one PDF or photos in page order: previews through object URLs, freed on remove and unmount; reorder, remove, limits from `/api/subjects`; server refusals shown under it), `add-chapter-form.tsx` (wraps it; also `SourceField`/`sourceFits` for the text editor), `chapter-row.tsx` and `chapter-state-card.tsx` (« Lecture des pages… (n/N) » while the pages are read; « Redéposer le document » instead of « Réessayer » when a run failed before its transcription was stored, linking to `…/content?tab=source`), `content/` (pack, path and source editors; the source tab is « Texte extrait du document » with « Remplacer par un document »).

The first-run `/setup` route (spec 013) is public and server-rendered like `/register`; `authConfigQuery` returns `{registration, setupRequired}` and `login.tsx` / `register.tsx` redirect to `/setup` while the instance waits for its first administrator. The admin-only « AI provider » section (spec 014: `settings/ai-section.tsx`, with the form's rules in `settings/ai-form.ts` and the provider presets in `lib/ai-presets.ts`; `SettingsSection.roles`) and the dashboard's `AiBanner` read `lib/admin.ts` (`aiSettingsQuery`, `afterAiChange`) and `useHealth().aiConfigured`. The voice session posts its SDP offer to the `calls_url` the backend sends, never to a URL of its own.

The product's name is `APP_NAME` in `src/lib/brand.ts` (a proper noun, the same in every language, so not in the catalog; the file is on the French-literal allow-list and the English sweep ignores it), and the logo is `src/assets/celestin-mark.svg`. Use them instead of typing the name or importing an image.

`src/components/ui/` is stock shadcn/ui. Prefer adding a component there over hand-rolling one, and keep product-specific pieces in `celestin/`.

## Styling

`src/styles.css` is the whole design system: a `@theme inline` block maps CSS variables to Tailwind utilities, then `:root` and `.dark` define values. All colours must be `oklch`. Adding a semantic colour means three edits — a `:root` value, a `.dark` value, and a `--color-<name>` registration in `@theme inline`.

Beyond the shadcn defaults the theme adds `paper` (the whiteboard's ground), `board`, `quote` (the pink highlighter used for text quoted verbatim from the course), `success`/`warning`, and the `shadow-sheet`/`shadow-sheet-lift` elevations. Custom utilities defined with `@utility`: `math-display`, `course-quote`, `board-enter`, `panel-down`, `chart-grow` / `chart-trace` (a chart draws itself once; also used by figures, plots and flowchart edges) and `flow-enter` (a flowchart's rows appear in turn, the delay set inline; not on a redisplay that walks a `path`); these three are off under reduced motion. Charts use `--chart-1…8`.

Design intent from the README: modern, sober, functional, Khan Academy in spirit. Math is the hero on the board. Colour signals state, not decoration.
