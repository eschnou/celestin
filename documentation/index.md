# Documentation

How the parts of this repository actually work, for whoever picks it up next.
Product intent lives in `specs/product.md`; per-feature specs live in `specs/NNN-*/`.

| Page | Covers |
|---|---|
| [tutor-turn-pipeline.md](./tutor-turn-pipeline.md) | One conversation turn end to end: prompt assembly, the tool loop, the SSE contract, and the prompt-caching rule that decides what a turn costs. It also covers the typed board blocks and their tool rules: the string checks for text the board would show raw, definitions, and the four drawing blocks (charts, flowcharts, figures, plots) with their refusal codes, logs, rendering, probes, known limits and manual checklists. Why the three newer drawing blocks were built as they are is in `specs/009-board-drawings/` |
| [chapters.md](./chapters.md) | A chapter as a pack plus a curriculum: the transcription and its marks (drawings included), the subject pack templates and their ids (the representations a pack names), the curriculum and its references, editing and versions, the three section kinds, the locked path, where progress lives, what the strip and the map show |
| [authoring.md](./authoring.md) | From a document to a chapter: reading uploaded PDFs and photos, the prompt files and how to add a subject, the transcription stage and the two authoring stages with their repairs, the runner's limits, progress and states, failure messages, cost, the eval scripts |
| [accounts-and-courses.md](./accounts-and-courses.md) | Students with accounts and their courses: sessions and roles, courses and chapters owned per student, the routes, progress owned by the server, migrations, the authenticated frontend routes and pages |
| [admin.md](./admin.md) | Registration modes (open, closed, verification), disabled accounts, the admin role and the one command that creates one, the dashboard (list, enable, disable, reset a password) and the password change, routes, failure behaviour, manual checklist |
| [discussion.md](./discussion.md) | The second mode: a free conversation about a chapter, the two locks that keep it off the student's path, the mode's prompt layers and its own cached prefix, the stored conversation and its caps, the routes, and what the interface shows |
| [lesson-layout.md](./lesson-layout.md) | The séance screen on a desktop and on a phone: the two frames and how one is chosen, the phone's bar, path strip, board, caption and composer, the keyboard (visual viewport), how the tests pick a layout, what is not done |
| [voice.md](./voice.md) | Talking to Célestin: the browser-held Realtime call (the telephone button), the three `/api/voice` routes, how tool calls are bridged, the seed, the voice block of the prompt, cost and failure behaviour; and dictation, the composer's microphone (the take and how it ends, `POST /api/dictation`, which model and server, configuration) |
| [work-reading.md](./work-reading.md) | The camera in the composer: a photo of her handwritten work read into text by the transcription model, corrected by the student and sent as an ordinary message; why the tutor never sees the picture, `POST /api/courses/{id}/work`, the prompt, the phone's camera and gallery, the computer's webcam, limits, what is not done |
| [course-language.md](./course-language.md) | A course's language (French or English): where it lives and flows, the `by_language` tables, the per-language prompt files and what the English set keeps, authoring and the transcription's marks, the tool declarations and their overlay, the board's notation and the learner sentences, how to add a language or a subject in one, the English probes |
| [i18n.md](./i18n.md) | The interface language (French or English): which language when, the frontend catalog and its conventions, the backend message catalog, the wall that keeps the model's input independent of it, the guards and tests, the hosting cache rule, how to add a string, a server message, a settings section or a language |
| [first-run-setup.md](./first-run-setup.md) | A fresh instance configured in the browser: the first-run state and `/setup` (first visitor wins), secrets generated into `SECRETS_DIR`, the OpenAI key stored encrypted and changed without a restart (the provider hub), the needs-key state and its `503`s, `COOKIE_SECURE=auto`, the backup before a migration |
| [ai-providers.md](./ai-providers.md) | Running on any OpenAI-compatible provider (spec 014): a connection (address, key, API style) and a model, reasoning effort and optional own connection per role, set in the browser or the environment (environment wins); the Responses and Chat Completions adapters and what they change for a server that is not OpenAI's; structured-output modes; the test action and its live checks; voice on its own connection; cost logging; what was verified on which model. |
| [docker.md](./docker.md) | The single image (web app, tutor service and Caddy): what runs in it and how, configuration and the defaults it sets, first admin, upgrading and backing up, the GitHub Actions workflow that tests, smoke-tests and publishes the multi-architecture image to ghcr.io, releasing a version, what it does not do |
| [running-locally.md](./running-locally.md) | Starting both processes, configuration, and the checks that prove it works |
