## Fixes after verification

`/sdd:verify` (code review + spec compliance) found no critical or high issue. Fixed, with tests (backend 538 → 546, frontend 196 → 198); `scripts.smoke` rerun: `CACHE OK`, 13 419 cached tokens.

1. **A finished run overwrote edits saved while it ran.** Pack and path saves are refused with `409 authoring_running` while a run is in progress, in the adoption's own `WHERE` (not a prior read), and the content page disables its editors meanwhile.
2. **An unexpected error could log the student's content.** `authoring_internal_error` and `authoring_fail_not_stored` log the exception type only; a database error's message carries the bound pack and curriculum.
3. **A pack containing `<!-- CURRICULUM -->` received the path overview.** The three markers are substituted in one pass over the tutor prompt only.
4. **A turn could save progress naming sections of an older path** after an edit deleted it, inflating the course page. `ProgressRepository.save` takes the content version the turn loaded and refuses a stale write (a tool error to the model); `LessonChapter.version` is back for that.
5. **« Réessayer » on a running chapter answered `nothing_to_retry`**: now `authoring_running`. **A refused retry from the lesson page was silent**: the message is shown.
6. **Log fields of design §9**: `course_id` on every `authoring_*` line, per-stage ms and tokens on success and failure, `ms` per stage attempt, `progress_reset` on `chapter_content_saved`.
7. **Labels**: « En préparation… » / « Échec de la préparation », « Contenu du chapitre » on the course page, « Nouveau chapitre N » on the content page (`position` added to `ChapterContent`), « Reprendre » only on the chapter worked on last (« Continuer » on the others).

Not fixed, deliberately: `subject` on `turn_complete` (the turn context carries no subject; `chapter_id` identifies it), the run timeout starting after the semaphore (at most 4 runs queue), limits shown up front in the add-chapter form and the reset warning outside the confirmation, seed credentials as arguments, no offline test fed with `injection.txt` (delimiting is tested, behaviour checked by the eval), pack and references not revalidated on read, deleting a course not cancelling its run, the `Content-Length`-only body cap (from 004), and the rare shutdown/`finish_failed` races.

## Deviations

1. **Exercise pools may reference a pack section** (design §3.6). The chapter 1 path draws exercises from the §4.4 applications table and from the definitions to recite, which have no `N.M.K` id. `reference_issues` accepts an `exercises` entry starting with either an exercise id or a `§` id that exists in the pack; the synthesis pool of chapter 1 was rewritten with `§` ids. The authoring curriculum prompt says so.
2. **Authoring prompts written in Phase 0** (task 2.3), so `PromptLibrary.check()` requires the final file set from the start instead of growing it in Phase 2.
3. **`load_chapter_dir(directory, subject, prompts, chapter_id=None)`** takes the prompt library (it needs the subject's template); the curriculum keeps its own id unless one is given.
4. **One adoption method instead of `save_pack` / `save_curriculum`** (design §3.10). `ChapterRepository.adopt_content(chapter_id, pack, title, curriculum, expected_version=None)` is the single transaction (content, version + 1, progress deleted) used by the pack editor, the curriculum editor and the seed; the routes validate first, and `expected_version` makes it refuse a stale edit. The runner's `adopt_authored` wraps the same private helper in Phase 2.
5. **Repository helpers for the seed and tests**: `CourseRepository.find_by_name`, `ChapterRepository.first_of`, and optional explicit ids on `create`, so `scripts/seed.py` is idempotent and tests address chapter 1 at fixed ids (`tests/conftest.py` `LESSON`). `list_for_user(user_id, course_id=None)` also serves the course detail (one query either way).
6. **`test_deps.py` not created**: ownership (foreign course, foreign chapter, chapter of another course of the same student) and 409-not-ready are covered through the routes in `test_courses_endpoint.py` and `test_chat_endpoint.py`, which exercise the same dependencies end to end.
7. **Eval material**: `maths_second_degre.txt` instead of the planned `maths_suites.txt` (a chapter other than the seeded one), `physics_mru.txt`, `injection.txt`; both subject samples carry a deliberately wrong correction.
8. **Runs closed on a deleted chapter are `failed` / `discarded`** rather than `succeeded`, so a run row always says whether content was adopted. The quota still counts them.
9. **Authoring 202 responses are built from the record the runner returned**, not re-read, so a run that finishes before the response is written cannot answer `idle` for a chapter that was just submitted. `AuthoringRunner.wait_idle()` exists for tests.
10. **`/api/health` `authoring_active` counts running rows in the database**, not the in-process task set: the same number in one process, and still meaningful if a second process ever runs.
11. **Inline forms instead of dialogs for creating and renaming a course** (design §3.16): the create form opens in the page and the rename form replaces the title. Easier on a phone and in tests; confirmations of destructive actions still use `AlertDialog` (`confirm-dialog.tsx`). Subjects are native radio inputs.
12. **`src/test/route-harness.tsx`** mounts file routes under jsdom with a scripted `fetch`, shared by the new route tests (the 004 tests each rebuilt their own tree).
13. **The lesson route follows the course query while not ready** and opens the lesson once the chapter is ready, instead of a static card.
14. **Beats, exercise pools and pack references are one textarea per list, one item per line**, rather than nested field arrays: the same data, far simpler for a student to edit, and the lines are trimmed and emptied out before sending.
15. **Pack headings render one level down** (`#` → `h2`): the content page owns the `h1`.
16. **`Math` hardened**: `trust: false` explicitly, and the fallback when KaTeX throws is HTML-escaped (it returned raw TeX into `innerHTML`, which pasted material could exploit). Test `math.test.tsx`.
