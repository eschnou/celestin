# 013 — Tasks

Phases are testable increments in dependency order. Each ends with a check the user can run. Requirement ids (`R1`…) refer to `requirements.md`, section numbers (`§`) to `design.md`. Tick tasks as they land; record design deviations in the Deviations section at the end.

Work on `feature/first-run-setup`, branched from `chore/docker` (which holds the image this epic changes; its own commit comes first). Not merged until the user says so.

Checks for every phase that touches a side: backend `cd backend && uv run pytest`; frontend `cd frontend && npm run typecheck && npm run lint && npm test`.

Constraints across the epic:

- **Nothing existing changes behaviour** when `SECRETS_DIR` is unset and the environment variables are set (R4.9, R11). The only edits to existing tests are the ones forced by R3 (registration refused on an empty database) and by the `AuthConfig` shape, named in 1.6 and 5.3.
- Only `app/providers/` imports `openai` (§4.1 of the requirements, §3.6).
- No log line, response, error or test output carries the API key or a secret (R4.7, R5.9). Every phase that handles the key has a `caplog` assertion.

## Deviations
