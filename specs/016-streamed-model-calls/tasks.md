## Deviations

Recorded as they appear. Known from planning:

- Design §5 names `formatInt`; the repository's helper is `formatCount` (`lib/i18n-format.ts`).
- `ai_test.py` and `work_reading.py` need no code change (R2.6); only tests.
- `test_openai_probe.py:68` and `test_provider_client.py:15,23,35` assert `max_retries`; they change in 1.2 because the parameter is removed.
- `StreamTimeout` and `StreamBroken` live in `providers/base.py` (re-exported by `streaming.py`), not in `streaming.py`: `_errors.translate`/`classify` must name them and `streaming.py` imports `_errors`, so defining them in `streaming.py` would be a cycle.
- `CallStats.begin()` is the constructor adapters use (it reads the loop clock); `failure()` always takes a `CallStats` (the tutor `stream()` makes one at the call start, so it has no `received_chars` but a real `elapsed_ms`).
- SDK mock transports in tests are `httpx2` (the SDK's own copy of httpx), not `httpx`.
- `completion_result` gained a `streamed_text` parameter (the deltas joined) instead of a synthetic response object: the final response's own text wins, the deltas are the fallback (§3.5).
- `streaming.fail(exc, …, only_provider=False)` is the raise helper the adapters call from `except`; the tutor's `stream()` passes `only_provider=True` so an exception raised by the stream's consumer (not the provider) is neither translated nor logged as a provider failure. Not in the design; the design's `failure()` is unchanged underneath.
- The Responses and Chat adapters keep `_translate` importable from their module (their tests import it); it is no longer used there.
- `LiveProgress.begin_call(stage, attempt)` and `for_call(stage, attempt)` derive « counted » from the stage (`pack`, `curriculum`) instead of taking a `counting` flag as the task list sketched: a page batch can only be a transcription stage call.
- `settle()` is awaited after a successful call only; a failed or cancelled call ends the run, which clears the count, and `LiveProgress.close()` (runner `finally`) drops a pending write.
- `tests/fixtures/fake_completion.py` gained `streamed(step, *received_chars, hold_s=…)`: a scripted step that reports snapshots (and stays open `hold_s`) before answering or raising.
- No progress line is logged while a provider is completely silent (a snapshot is emitted per event); a stall is visible as the log going quiet, then `provider_call_failed … idle_timeout`.
- The plural message `chapter_received_chars` takes two variables: `count` (the number, for the plural rule) and `shown` (the same number formatted by `formatCount` for display), so the digits are grouped by the interface locale and French still counts 0 and 1 as singular.
- The preparation card's text is a `<div aria-live="polite">` holding one paragraph per sentence (the stage line and, when slow, the notice) instead of one `<p>`, so both sentences sit in the same live region.
- After the `/simplify` pass: `classify` returns `CallDiagnostics` itself (no `Classification` twin; the caller adds elapsed, idle and characters); `AuthoringFailed` carries `diagnostics` (the runner no longer reads `exc.__cause__`); `COUNTED_STAGES` lives in `domain/chapter.py` with `ChapterRecord.live_received_chars` and `quiet_seconds(now)` (the route only maps them); `LiveProgress.restart_count()` replaces `begin_call` and is called for repair attempts only, since starting a stage already zeroes the count (a page batch no longer writes before its call); the streamed text is the answer and the final response's `output_text` the fallback; `consume` anchors its first-event deadline when it starts, so the Chat adapter's `max_tokens` second attempt gets its own allowance; the done log reads tokens with `read_usage` (null = not reported).
- Skipped from the review, on purpose: splitting `streaming.py` into watching and reporting modules, moving the done/failed logs into the recording wrapper, and removing `fail(only_provider=True)` by narrowing the tutor `stream()` try (larger reshaping of working, tested code); throttling the idle `reschedule` and the one-write-per-second progress store (micro-costs, more timing logic); merging `_Writer` into `LiveProgress`; a null-object `LiveProgress`; dropping the `AUTHORING_CALL_TIMEOUT_S` shim (required by R3.3); removing `chat_result` (the reference the streamed-vs-whole tests compare against); a shared frontend `ChapterRow` test builder.
- **Not run (8.3):** the real-provider checks (`scripts.smoke`, `scripts.authoring_eval`, a 26-page PDF through `scripts.document_eval` and through the UI), because they spend the provider key. The streamed paths are proven against scripted streams only; time to first event, characters per second and the first real `provider_call_failed` are still to be recorded here.
