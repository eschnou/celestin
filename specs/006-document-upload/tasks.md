## Deviations

1. **PDF page count shown after upload** (requirements NFR 4.5.2), per design decision 8.
2. **p. 5 acceptance amended** (requirements R2.3, NFR 4.4.4). The requirement asked for the boxed 330/350 on chapter 1 p. 5 to come out `[incertain`. On the rendered page the figure reads 330 and agrees with its own line (33 · 10), and both eval runs read it right. What the requirement protects against is a wrong reading presented as sure, so the eval now checks that p. 5 reads 330 and never a bare 350 (`p5_boxed_answer_not_misread`). Doubt marking itself is still required by the prompt and counted per run.
3. **Handwriting check off by default** (design 3.6, §6): decided by the eval above, as the design allowed.
4. **Run trigger `replace`** for a new document on an existing chapter (the design did not name one); `ck_authoring_runs_trigger` widened in migration 0004.
5. **One `on_progress(stage, pages_done)` callback** on `AuthoringAgent.run` for page counts and the pack → curriculum transition (design 3.5 names `on_pages` only). Progress writes are serialised in the agent so `pages_done` never goes backwards. A failure's stage is the one the chapter row holds (`finish_failed` reads it), not re-derived from attempt counters: a timeout after the transcription is stored stays retryable.
6. **Retry refusal keyed on the stage alone**: `start_retry` raises `DocumentNeeded` when the chapter's last failure is at `transcription`. A chapter whose source is empty has necessarily failed there, so the design's second condition is covered.
7. **Messages for transcription-stage failures**: `provider`, `timeout`, `interrupted` and `internal` at stage `transcription` say to drop the document again (`TRANSCRIPTION_MESSAGES`), since « Réessayer » cannot work there.
8. **An empty upload** (no `files` field, including a JSON body) is refused with `422 document_invalid` « Le document est vide. » rather than FastAPI's validation error; the removed JSON route therefore answers 422.
9. **French file button**: the native file input is visually hidden behind a « Choisir un PDF ou des photos » label (the browser's own button text is in the browser's language and says « no file chosen » after each pick, since the field is reset).
10. **No minimum length for a transcription**: `chapter_text_min_chars` applies to the text editor only; a document with little text (e.g. three short exercises) is prepared.

## Fixes after `/sdd:verify`

- A streamed body over the cap (no `Content-Length`) answered FastAPI's English 400: the middleware now replaces whatever the app sends with its own 413 (`document_too_large` / `payload_too_large`). Integration tests with chunked bodies.
- A text edit or retry of a document chapter reset its `page_count` to 0: a text run no longer touches the chapter's page counts. Integration test for a corrected transcription.
- `DocumentService._reset` drops only the pool that failed, so a late failure from an old pool cannot kill its replacement.
- A photo is decoded inside the refusal's `try` (a truncated file is « La photo N est illisible »), and Pillow's decompression-bomb warning (40–80 MP) is a refusal too.
- `AuthoringRunner.check_can_start` refuses (busy, quota, chapter limit, already running) before the document is rendered, so a refused upload does not hold a shared worker.
- `DOCUMENT_MAX_PAGES` raised from 30 to 50 at the user's request (2026-09-20): design §3.8 and the performance note updated. Measured on chapter 1, 50 pages means roughly 130–150 s of transcription and about 1,7 USD, and roughly 75 000 characters, still under `CHAPTER_TEXT_MAX_CHARS` (100 000).
- Deferred: transcription tokens on the run row and the extra log fields of design §9 (R7.1–R7.2 partially: time, cost, attempts and marks are stored); `verify.fr.md` required even when the check is off.
