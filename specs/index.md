## Feature Specs

| # | Slug | Description | Status |
|---|------|-------------|--------|
| 001 | [tutor-chat-agent](./001-tutor-chat-agent/) | Agentic AI tutor in the chat column, with an external prompt, the chapter 1 pack injected, and tools that drive the whiteboard | Implemented |
| 002 | [chapter-sections](./002-chapter-sections/) | Chapter 1 trimmed to sequences; a chapter becomes `pack.md` + `curriculum.yaml`; locked path of teach / practise / synthesis sections with section tools, client-held progress and a chapter map | Implemented |
| 003 | [realtime-voice](./003-realtime-voice/) | Voice mode on the OpenAI Realtime API: same prompt and tools, browser-held WebRTC session with a backend-minted client secret, tool calls bridged from the browser to a backend tool endpoint, one transcript across text and voice | Implemented |
| 004 | [accounts-and-classes](./004-accounts-and-classes/) | Registration and sign-in, roles (student implemented), a class catalog from the course files, enrolment, a class page with per-chapter progress, progress owned by the server per student and chapter, multi-chapter tutor | Implemented |
| 005 | [student-authored-courses](./005-student-authored-courses/) | Pivot to self-service: students create courses (name + locked subject) and add chapters by pasting text; an authoring agent produces pack and curriculum; content in the database; tutor prompt split into tutor and subject layers; mathematics and physics first | Implemented |
| 006 | [document-upload](./006-document-upload/) | Chapters from an uploaded PDF or photos, replacing pasted text: a vision-model transcription stage (page markers, handwriting and doubt marked) before the spec 005 authoring pipeline; the file is not kept; limits, costs and failure handling of spec 005 | Implemented |
| 007 | [discussion-mode](./007-discussion-mode/) | Discussion mode: free conversation about a chapter beside the parcours — the board but no section tools, so no progress is written; conversations stored per student and chapter with « Nouvelle conversation »; a brought statement is a base of discussion, never a request for a solution | Implemented |
| 008 | [board-charts](./008-board-charts/) | Statistical charts on the board: a `chart` block (bar charts, histogram, polygons, pie chart, box plot) drawn by our components from data Célestin supplies and the tool validates; the course's notation; no chart gives an answer away; the pack records the course's representations. `plot` and `figure` are later specs | Implemented |
| 009 | [board-drawings](./009-board-drawings/) | Three more drawing blocks next to 008's charts: `flowchart` (organigrammes laid out by the board, `path` walk-throughs, `hidden` boxes to complete), `figure` (plane geometry with its codage, number lines, diagrams of sets) and `plot` (functions, sequences and measurements in a repère, from our own expression grammar). One `Drawing` union, one dispatch table, at most two drawings per card; the tool refuses what it can see of an answer on an exercise's drawing; string checks for LaTeX left raw | Implemented — no SDD: reviewed designs archived |
| 010 | [interface-language](./010-interface-language/) | French and English interface: the browser's language on the first visit, kept on the account at registration and changed only on a new settings screen (« Paramètres », built to receive name, email and password settings later); every frontend string in a typed catalog, and the backend's student-facing messages (errors, statuses, labels, content issues) localized by request language. Course text, the tutor, the board's notation and everything sent to the model stay French and byte-identical; the course language is a follow-up spec | Implemented — English copy awaiting review |
| 011 | [course-language](./011-course-language/) | A course has a language (`fr` or `en`), chosen at creation and immutable: the language of its material, pack, curriculum, Célestin's speech, voice and the board's notation. An English prompt set beside the French one (which does not move), English authoring and transcription (per-language markers and pack templates, no translation), model-facing text built in code made language-aware, tool rules that recognise English vocabulary and notation, the board's formatters and the learner sentences per course language, voice, and English probes, fixtures and goldens with French pinned byte for byte. Independent of spec 010's interface language | Implemented — English prompts and probe runs awaiting review |
| 012 | [admin-and-registration-modes](./012-admin-and-registration-modes/) | Admins and registration modes: `users.enabled` and `REGISTRATION_MODE` (`open`, `closed`, `verification`: in the last, sign-up creates a disabled account until an admin enables it; in `closed`, no sign-up and no link); the `admin` role and an `/admin` dashboard to list accounts, enable or disable one and reset a password (shown once, sessions ended); a password change in the settings; admins made only by `scripts/create_admin.py` | Implemented — no SDD: decisions archived |
| 013 | [first-run-setup](./013-first-run-setup/) | A self-contained install: `docker run -p 8080:8080 -v ./data:/data <image>` with no environment variables. A first-run `/setup` page (first visitor wins, only while `users` is empty) creates the admin; the admin pastes the OpenAI key in a settings section (stored encrypted, env var wins, tutor/authoring/realtime clients swapped at runtime, a needs-key state with clear `503`s); session secret and encryption key generated into `SECRETS_DIR`; `COOKIE_SECURE=auto`; a database backup before a pending migration (`scripts.migrate`); the entrypoint fixes `/data` ownership; existing env-var deployments unchanged | Implemented — the Docker image was not built or run (host disk full): `docker build` then `docker/smoke.sh` remain |
| 014 | [ai-provider-configuration](./014-ai-provider-configuration/) | Run on any OpenAI-compatible server, set in the admin UI: a default connection (base URL, key, API style `responses` or `chat`) and a model, reasoning effort and optional own connection per role (tutor, authoring, transcription, voice); presets (OpenAI, Groq, OpenRouter, Ollama, custom), model suggestions, a per-role test with optional live checks; a Chat Completions adapter beside the Responses one; structured-output mode `schema` or `json`; environment wins, existing variables unchanged; the stored OpenAI key keeps working; voice only on a Realtime-capable connection (calls URL from the server); honest cost logging; smoke and probe scripts on the effective configuration. Responses API verified on Groq `openai/gpt-oss-120b` | Implemented — Docker image not built (no registry access here); live-verified on Groq; gpt-oss cannot drive the tutor |
