# 015 — Tasks

Phases are testable increments in dependency order. Each ends with a check the user can run. Requirement ids (`R1`…) refer to `requirements.md`, section numbers (`§`) to `design.md`. Tick tasks as they land; record design deviations under the phase's **Verified** line.

Work on `feature/015-ai-usage-logging` (the `sdd:go` convention, as 014), branched from `main`. Not merged and not pushed until the user says so.

Checks for every phase that touches a side: backend `cd backend && uv run python -m pytest`; frontend `cd frontend && npm run typecheck && npm run lint && npm test`.

Constraints across the feature:

- **No content in the ledger** (R7): nothing a student wrote, said or uploaded, no provider error text, in a row, a log line or an answer. Phase 3 holds the test that proves it.
- **The ledger never gets in the way** (R5): every recording path is wrapped so a failure is a log line, never an error for the caller.
- **No price is applied** (R3): `Settings` price fields are not read by any new code.
- Only `app/providers/` imports `openai`; `app/providers/` imports nothing from `app/db` (test added in 2.1).
- French and English copy for every new interface string (spec 010); the model never reads any of it.
- Between 1.2 (the migration drops `voice_usage`) and 1.4 (the voice route writes the ledger) the voice route is broken: the branch is not pushed in that window.
